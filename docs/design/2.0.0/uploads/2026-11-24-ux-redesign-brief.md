# clrc — бриф на редизайн UX (iOS)

Дата: 2026-11-24. Основа: текущий код ветки `feat/structured-output`.
Скоуп: только UI/UX iPhone-приложения. Бэкенд-зависимости помечены **[backend]** и в этот редизайн не входят, но экраны под них проектируем сразу.

---

## 1. Цель продукта

**clrc — пульт управления Claude Code на своих Маках с iPhone.** Claude работает на Маке в реальном проекте, а человек с телефона ставит задачу, следит за ходом, отвечает на вопросы и проверяет результат, включая код-ревью.

Главная мысль: **телефон — для чтения и решений, а не для набора текста.** Печатать на телефоне неудобно, а читать, листать, нажимать кнопки и одобрять — удобно. Каждый экран должен минимизировать набор текста и максимизировать «понял статус за 2 секунды → принял решение одним тапом».

### Кто пользователь
Один разработчик (владелец Маков), технически сильный. Использует приложение:
- в дороге, на встрече, на диване — короткие сессии по 10–60 секунд;
- одной рукой, часто без звука;
- чтобы не ждать у компьютера, пока Claude закончит.

### Ключевые сценарии (по частоте)
1. **Проверить статус**: «Claude закончил? Ждёт ответа? Упал?» — с одного взгляда, без входа в сессию.
2. **Ответить на вопрос Claude**: выбрать вариант 1/2/3, «да», «продолжай» — одним тапом.
3. **Посмотреть, что изменилось**: список файлов и diff после хода Claude.
4. **Поставить новую задачу** в проекте: выбрать Мак → проект → режим → коротко описать (часто голосом).
5. **Ревью кода из GitLab**: открыть MR, пролистать diff, оставить комментарий к строке, approve или отправить Claude на доработку. **[backend]**
6. **Аварийный терминал**: Ctrl+C, `git status`, перезапустить что-то. Редко, но должно работать.

### Метрики удобства (на них проверяем редизайн)
- Статус всех сессий виден **без единого тапа** после открытия приложения.
- Ответ на вопрос Claude — **≤ 2 тапа** от открытия push-уведомления.
- Новая задача в недавнем проекте — **≤ 3 тапа** плюс текст.
- Клавиатура **никогда не открывается сама** (кроме экрана, где цель — ввод текста, и только по явному действию).
- При открытой клавиатуре контента видно **не меньше 50 % экрана**.

## 2. Принципы UX

1. **Чтение по умолчанию, ввод по требованию.** Экраны открываются в режиме просмотра. Клавиатура появляется только по тапу на поле ввода.
2. **Статус — первым.** Карточка итога хода (`report`: статус, заголовок, summary, вопросы, файлы) — главный элемент, текст Claude — детали.
3. **Тапы вместо текста.** Вопросы → кнопки, частые ответы → чипы («Продолжай», «Да», «Нет», «Покажи diff», «Запусти тесты»), голос → полноценный способ ввода.
4. **Одна рука.** Основные действия — в нижней трети экрана. Верхний край — только навигация и статус.
5. **Код читается как код.** Моноширинный шрифт, подсветка синтаксиса, перенос строк по выбору, diff с номерами строк, горизонтальный режим.
6. **Безопасность видна.** Опасные режимы (`--dangerously-skip-permissions`, удаление папки, Close All) — всегда отдельным цветом и с подтверждением.
7. **Честные состояния.** У каждого экрана есть дизайн для пустого состояния, загрузки, ошибки, офлайна Мака и потери связи с relay.

### Сквозные проблемы
- **Клавиатура.** Терминал фокусируется автоматически; в чате поле ввода с клавиатурой занимает ~55–60 % высоты iPhone; нет способа «ответить, не открывая клавиатуру».
- **Нет «дома».** После первой сессии пользователь всегда внутри какой-то одной сессии, а общий статус спрятан в шторке.
- **Режимы спрятаны.** Chat / Brief / Terminal выбираются только в шторке New Session и в Settings.
- **Код нельзя ревьюить.** Нет diff, подсветки, комментариев, интеграции с GitLab.
- **Навигация сверху.** Основные действия (+, переключение сессий, настройки) — в верхней полосе высотой 44pt.

## 4. Целевая информационная архитектура

Нижний таб-бар из 4 вкладок, всё остальное — push-навигация внутри вкладки и шторки.

```
Tab bar
├── Inbox      — все сессии и события, сортировка «требует меня» → «работает» → «готово»
├── Review     — изменения от Claude и merge requests GitLab   [GitLab: backend]
├── Projects   — Маки → проекты → запуск задачи, браузер файлов
└── Settings   — подключение, отображение, профиль Claude, о приложении

Глобально
├── FAB / кнопка «Новая задача» (в Inbox и Projects)
├── Push-уведомления и Live Activity для активной сессии
└── Баннер связи (relay / Мак офлайн), единый для всех экранов
```

Сессия (чат или терминал) открывается из Inbox или Projects как полноэкранный push-экран. Таб-бар внутри сессии скрыт, чтобы отдать место контенту.

## 5. Экраны подробно

Для каждого экрана: **назначение → контент → действия → состояния → клавиатура**.

### 5.1 Онбординг и вход

**Назначение:** подключить телефон к своему relay за один шаг.

**Контент:**
- Название и иконка продукта, одна фраза: «Управляйте Claude Code на своём Маке с iPhone».
- Главная кнопка: **«Сканировать QR с Мака»** (QR показывает установщик или `clrc pair` на Маке).
- Второстепенная ссылка: «Ввести вручную» → Relay URL + пароль.

**Состояния:** нет камеры (симулятор) → сразу ручной ввод; неверный пароль → инлайн-ошибка под полем; relay недоступен → «Мак или relay не отвечает» с кнопкой «Повторить».

**Клавиатура:** только в ручном режиме; поле URL — `keyboardType: .URL`, без автокоррекции; кнопка «Войти» поднимается над клавиатурой.

### 5.2 Inbox (главный экран)

**Назначение:** с одного взгляда понять, что происходит на всех Маках, и сразу перейти к тому, что требует внимания.

**Контент — список карточек сессий, сгруппированных по срочности:**
1. **Ждёт вас** (`needs_input`, `failed`) — оранжевый и красный, наверху.
2. **Работает** (ход идёт) — индикатор активности, текущий инструмент («Edit main.go», «Bash: make test»), время с начала хода.
3. **Готово** (`done`) — зелёные, ниже.
4. **Терминалы** — компактные строки (имя, Мак, последняя строка вывода).

**Карточка сессии:**
- иконка статуса и цвет (как в `ReportCard`: done / needs_input / failed / in_progress);
- `title` последнего отчёта (1 строка) и `summary` (2 строки);
- мета: проект · Мак · «3 файла» · «2 мин назад»;
- бейдж контекста (зелёный / красный) — маленькая точка, не текст;
- если есть вопросы — **кнопки ответов прямо в карточке** (до 3; остальное — «Ещё…»).

**Действия:**
- тап по карточке → экран сессии (5.4 или 5.6);
- тап по кнопке-вопросу → ответ уходит сразу, без открытия сессии (с undo-тостом 3 секунды);
- свайп влево → «Стоп» (если работает) / «Закрыть»;
- свайп вправо → «Изменения» (сразу в diff хода, 5.8);
- долгий тап → переименовать, закрепить, открыть в терминале;
- кнопка **«Новая задача»** (FAB внизу справа или крупная кнопка в нижней панели).

**Состояния:**
- пусто → «Нет сессий» + кнопка «Новая задача» + недавние проекты;
- relay офлайн → баннер сверху, карточки в серой «последней известной» версии;
- Мак офлайн → карточки этого Мака приглушены с пометкой «Мак не в сети»;
- завершённые сессии («tombstones») → свёрнутая секция внизу «Завершённые» с кнопкой «Перезапустить в том же проекте».

**Клавиатура:** нет.

### 5.3 Новая задача (шторка)

**Назначение:** запустить Claude в нужном проекте за ≤ 3 тапа.

**Структура сверху вниз:**
1. **Мак** — чипы, если Маков больше одного (по умолчанию — Мак текущего или последнего проекта).
2. **Проект** — недавние проекты крупными строками (имя папки + путь мелко); последняя строка — «Выбрать папку…» (браузер 5.9 в режиме выбора).
3. **Задача** — многострочное поле «Что сделать?» (необязательно) + кнопка микрофона + чипы-шаблоны («Почини тесты», «Сделай ревью ветки», «Объясни код»…). Если поле пустое — сессия стартует без первого сообщения.
4. **Режим** — сегменты **Chat · Brief · Terminal** (запоминается). Под ними одна строка пояснения.
5. **Дополнительно** (свёрнуто): имя сессии, модель, профиль Claude, «Без подтверждений (опасно)» — красный переключатель с подтверждением.
6. Главная кнопка внизу: **«Запустить»**; вторичная ссылка: «Пустой терминал».

**Поведение:**
- тап по недавнему проекту при пустом поле задачи → сразу запуск (1 тап);
- шторка открывается в средней высоте (`.medium`), поле задачи не в фокусе;
- при фокусе на поле шторка растёт до `.large`, а проект и режим остаются видны компактной строкой над полем.

**Клавиатура:** только по тапу в поле «Что сделать?»; кнопка «Запустить» — в accessory-панели над клавиатурой.

### 5.4 Сессия: чат (режимы Chat и Brief)

**Назначение:** следить за работой Claude, читать ответы, отвечать.

**Шапка (компактная, 44pt):** назад · имя сессии и проект (тап → меню: переименовать, сменить вид Chat/Brief, открыть терминал этого проекта, закрыть сессию) · точка контекста · индикатор работы.

**Лента:**
- **Сообщения пользователя** — пузыри справа.
- **Ход Claude:**
  - *Chat*: markdown-текст (заголовки, списки, `code`, блоки кода с подсветкой и кнопкой «Копировать»), затем карточка итога;
  - *Brief*: карточка итога первой, текст свёрнут в «Подробности».
- **Вызовы инструментов** — одна свёрнутая строка на ход: «🔧 7 действий: Read ×3, Edit ×2, Bash ×2» → раскрытие показывает список; каждый вызов раскрывается до input/output (моно, с переносом, «Показать полностью»). Bash-вывод с ошибкой — красная полоска слева.
- **Карточка итога (`report`)** — главный элемент:
  - статус-иконка, `title`, `summary`;
  - «N файлов изменено» → **тап открывает diff хода (5.8)**, а не просто список путей;
  - `next_steps` — серыми строками;
  - `questions` — крупные кнопки «1. …», «2. …»; тап **сразу отправляет ответ** (с undo), долгий тап — подставляет в поле для редактирования;
  - стоимость и длительность хода — мелко в углу.
- Разделители дат и «новые сообщения» при возврате в сессию.

**Нижняя панель (режим чтения, по умолчанию):**
- ряд **чипов быстрых ответов**: контекстные (вопросы из report) + постоянные («Продолжай», «Да», «Нет», «Покажи diff», «Запусти тесты», «Закоммить»); набор редактируется в Settings;
- однострочная «пилюля» **«Ответить…»** + кнопка микрофона + кнопка «Стоп» (когда Claude работает).

**Нижняя панель (режим ввода, по тапу на «Ответить…»):**
- поле растёт до 5 строк, дальше — скролл внутри;
- accessory-панель над клавиатурой: «Отправить», «Вставить путь файла» (из changed_files), «Шаблоны», «Спрятать клавиатуру»;
- лента продолжает скроллиться, **свайп вниз по ленте прячет клавиатуру** (`scrollDismissesKeyboard(.interactively)`);
- после отправки клавиатура **закрывается** и панель возвращается в режим чтения.

**Состояния:** Claude работает (живой индикатор, текущий инструмент); ход прерван («Прервано» + «Продолжить»); ошибка хода (красная карточка + «Повторить»); переподключение (лента не прыгает, догружает пропущенное); нет шапки контекста (красная точка + пояснение по тапу: «Сессия запущена без профиля или стиля clrc — проверьте CLRC_PROFILE на Маке»).

**Клавиатура:** никогда не открывается при входе в сессию.

### 5.5 Голосовой ввод (оверлей)

**Назначение:** сказать задачу вместо набора текста.

Удержание микрофона → полоса волны и живая транскрипция; отпускание → текст в поле (не отправляется сразу); свайп вверх при удержании → «отправить сразу». Язык распознавания берётся из настроек.

### 5.6 Сессия: терминал

**Назначение:** аварийный и ручной доступ к shell и Claude в TUI.

**Режим просмотра (по умолчанию):**
- терминал на весь экран, клавиатура **скрыта**;
- шрифт по умолчанию 13pt, пинч-зум 10–18pt (запоминается на сессию), поворот в горизонталь — больше колонок;
- выделение и копирование текста долгим тапом; тап по пути файла → открыть файл (5.10);
- внизу компактная панель: **«⌨︎ Клавиатура»**, Ctrl+C, «↑ история», «Команды…» (шторка с быстрыми командами по группам: Навигация, Git, Claude, Система — их можно редактировать).

**Режим ввода (по кнопке «⌨︎»):**
- над клавиатурой — **одна** строка спецклавиш: Esc, Tab, Ctrl (залипающий модификатор), ↑ ↓ ← →, `|`, `~`, `/`, `-`, «Спрятать»;
- терминал ужимается, но курсорная строка всегда видна (автоскролл к курсору);
- опционально «компактная клавиатура»: только accessory-строка + однострочное поле ввода команды (Enter отправляет всю строку) — системная клавиатура тогда нужна только во время набора.

**Состояния:** сессия переподключается (оверлей «Переподключение…», ввод заблокирован); процесс завершился («Сессия завершена» + «Перезапустить»); Мак офлайн.

**Клавиатура:** только по кнопке; **убрать автоматический `becomeFirstResponder`** при открытии.

### 5.7 Review — список

**Назначение:** собрать всё, что нужно посмотреть глазами.

**Две секции (сегменты сверху):**
1. **От Claude** — ходы с изменёнными файлами из всех сессий: title хода, проект, «N файлов, +X −Y», время. Источник — `report.changed_files` + diff с Мака. **[backend: diff по ходу]**
2. **GitLab** — merge requests: «Назначены на меня», «Мои», «Все в проекте»; строка MR — заголовок, `!номер`, проект, автор, ветки `source → target`, статус пайплайна (✓ / ✗ / ⏳), счётчик комментариев, «+X −Y». **[backend: интеграция с GitLab]**

**Действия:** тап → обзор MR (5.8); свайп → «Отметить как просмотренное»; фильтр по проекту.

**Состояния:** GitLab не подключён → карточка «Подключите GitLab» (URL инстанса + токен в Settings); пусто → «Нечего ревьюить 🎉».

### 5.8 Review — merge request / изменения хода

**Назначение:** удобно прочитать diff на телефоне и принять решение.

**Экран «Обзор» (первый):**
- заголовок, `!номер`, ветки, автор, статус пайплайна (тап → список джобов и лог упавшей);
- описание MR (markdown, свёрнуто после 6 строк);
- сводка: «12 файлов · +340 −120 · 5 обсуждений (2 нерешённых)»;
- **кнопка «Попросить Claude сделать ревью»** → запускает чат-сессию в проекте с задачей «сделай ревью MR !N», результат прилетает в Inbox;
- нижняя панель действий: **Approve** · **Комментарий** · **Ещё** (Merge, Закрыть, Открыть в браузере).

**Экран «Файлы»:**
- дерево или плоский список изменённых файлов с бейджами `A` / `M` / `D` / `R` и «+X −Y»;
- прогресс просмотра («7 из 12 просмотрено»), отметка «просмотрен» свайпом;
- фильтр: «только нерешённые обсуждения», «скрыть тесты», «скрыть lock-файлы и сгенерированное».

**Экран «Diff файла» (самый важный):**
- **unified diff** по умолчанию (split — только в горизонтальной ориентации на Pro Max);
- номера строк old / new в узкой колонке, `+` / `−` фоном строки, подсветка синтаксиса по расширению;
- **подсветка изменений внутри строки** (word diff);
- перенос длинных строк — переключатель (по умолчанию включён) + горизонтальный скролл, когда перенос выключен;
- неизменённые участки свёрнуты («⋯ 42 строки», тап — развернуть 20 / всё);
- навигация: следующий / предыдущий ханк (кнопки внизу или свайп), следующий файл; мини-карта изменений справа;
- поиск по файлу;
- **комментарий к строке**: долгий тап по строке (или выделение диапазона) → шторка комментария с превью строк; существующие обсуждения — инлайн-карточки между строками, свёрнутые до 2 строк, с «Ответить» и «Решить»;
- действие по строке: «Спросить Claude про эти строки» → вопрос уходит в чат-сессию проекта с контекстом файл:строки;
- шрифт: моно 12–13pt, пинч-зум, режим «тёмный код» независимо от темы.

**Изменения хода Claude** используют этот же экран, но без GitLab-действий; вместо Approve — **«Принять»** (ничего не делает, отмечает просмотренным), **«Откатить файл»** и **«Попросить исправить»** (открывает ответ в чате с цитатой). **[backend]**

**Клавиатура:** только в шторке комментария; шторка `.medium`, превью комментируемых строк остаётся видно над полем.

### 5.9 Projects

**Назначение:** найти проект и запустить в нём работу, посмотреть файлы.

**Уровень 1 — Маки:** карточки Маков (имя, онлайн/офлайн, число активных сессий, профиль Claude). Если Мак один — этот уровень пропускается.

**Уровень 2 — Проекты Мака:** недавние проекты (MRU) + «Все папки…»; строка проекта — имя, путь, ветка git и «грязное» состояние **[backend]**, активные сессии в проекте.

**Уровень 3 — Проект:**
- шапка: имя, ветка, кнопки **«Новая задача здесь»** и **«Терминал здесь»**;
- секции: «Сессии в проекте», «Изменения» (`git status`, тап → diff) **[backend]**, «Файлы» (браузер);
- **браузер файлов**: хлебные крошки сверху (тап — переход на уровень), поиск по имени, иконки по типу файла, размер и дата мелко; создание и удаление папок спрятаны в «⋯» (удаление — с подтверждением, красным).

**Режим выбора папки** (из «Новой задачи»): тот же браузер, внизу кнопка «Выбрать эту папку».

### 5.10 Просмотр файла

- Подсветка синтаксиса, номера строк, перенос по переключателю, пинч-зум.
- Поиск (лупа в шапке), переход к строке.
- Markdown-файлы — рендер с переключателем «Исходник».
- Действия: «Копировать путь», «Спросить Claude про файл», «Открыть в терминале» (`cd` в папку).
- Большие файлы (> 100 КБ): первые 100 КБ + плашка «Файл обрезан» (лимит агента — осознанный, см. CLAUDE.md).

### 5.11 Settings

Группы:
1. **Подключение** — relay (адрес, статус, «Переподключить»), Маки (имена, удалить), «Сканировать QR для нового Мака».
2. **Claude** — профиль по умолчанию, вид по умолчанию (Chat / Brief / Terminal), быстрые ответы (редактор чипов), шаблоны задач.
3. **Терминал** — размер шрифта, тема, набор быстрых команд, «Компактная клавиатура».
4. **Код** — тема подсветки, перенос строк по умолчанию, unified / split в горизонтали.
5. **GitLab** — URL инстанса, токен (хранится в Keychain), проекты по умолчанию. **[backend]**
6. **Уведомления** — когда уведомлять: needs_input / failed / done / ничего.
7. **Опасная зона** (отдельно, внизу, красным) — «Закрыть все сессии», «Выйти».
8. О приложении — версия, ссылка на логи агента (`clrc logs`).

### 5.12 Уведомления и Live Activity **[backend: push]**

- Push при `needs_input`, `failed`, `done` (настраивается): заголовок = `title` отчёта, текст = `summary`, **кнопки действий = вопросы** (ответ прямо из уведомления, без открытия приложения).
- Live Activity / Dynamic Island для активной сессии: проект, текущий инструмент, таймер хода; по завершении — статус и title.

## 6. Клавиатура — отдельные требования

Проблема сейчас: клавиатура плюс панели занимают около половины экрана, а терминал открывает её сам.

1. **Никакого автофокуса.** Ни терминал, ни чат, ни шторки не открывают клавиатуру при появлении. Исключение — экран, единственная цель которого ввод (ручной ввод URL при онбординге), и то только после явного тапа.
2. **Ответ без клавиатуры.** Вопросы и быстрые ответы — кнопки; голос — равноправный способ ввода.
3. **Свёрнутое поле ввода.** В режиме чтения поле — однострочная пилюля; разворачивается только при фокусе.
4. **Интерактивное скрытие.** Свайп вниз по ленте или терминалу прячет клавиатуру (`.scrollDismissesKeyboard(.interactively)`); кнопка «Спрятать» всегда в accessory-панели.
5. **Одна accessory-строка.** Никаких двух полос над клавиатурой (сейчас это QuickCommandBar + системная клавиатура). Спецклавиши терминала и действия чата — в одной строке высотой 44pt.
6. **Закрытие после отправки.** В чате после «Отправить» клавиатура уходит, лента прокручивается к новому ходу.
7. **Контент остаётся видимым.** При открытой клавиатуре последний ход или курсорная строка терминала всегда в видимой зоне; шапка сжимается до 32pt.
8. **Горизонтальная ориентация.** В терминале и diff поддерживается landscape: клавиатура там занимает меньше высоты, колонок больше.
9. **Аппаратная клавиатура.** Если подключена (iPad/Magic Keyboard) — accessory-панель минимальная, работают Esc, Ctrl, стрелки, ⌘K «Новая задача», ⌘. «Стоп».

## 7. Визуальный язык

- **Тема:** системная светлая/тёмная; код и терминал — всегда тёмная палитра (как сейчас `#1C1C21` / почти белый).
- **Цвета статусов (единые везде):** done — зелёный, needs_input — оранжевый, failed — красный, in_progress / работает — синий, неизвестно — серый. Опасные действия — красный, никогда не основной акцент.
- **Типографика:** SF Pro для интерфейса, SF Mono для кода, путей, команд и имён инструментов; поддержка Dynamic Type во всём, кроме терминала (там свой зум).
- **Плотность:** карточки с отступом 12pt, радиус 12pt; тап-зоны ≥ 44 × 44pt; основные действия внизу.
- **Иконки:** SF Symbols; у каждого инструмента своя иконка (Read — doc, Edit — pencil, Bash — terminal, Grep — magnifyingglass, Web — globe).
- **Движение:** короткие (≤ 0.25 с) переходы; карточка итога появляется с лёгким «подъёмом», индикатор работы — спокойная пульсация, без спиннеров на весь экран.
- **Доступность:** VoiceOver-лейблы для статусов («Сессия api: ждёт ответа, 2 вопроса»), контраст AA, не полагаться только на цвет (иконка + текст статуса).

## 8. Зависимости от бэкенда (не входят в этот UX-скоуп)

| Возможность | Что нужно | Где |
|---|---|---|
| Diff хода Claude | агент отдаёт `git diff` по `changed_files` хода | agent + протокол |
| git-статус и ветка проекта | `fs_git_status` / `git_branch` | agent + протокол |
| GitLab MR, комментарии, approve | токен GitLab в Keychain; запросы с телефона напрямую в GitLab API или через агента | iOS / agent |
| Push и Live Activity | APNs, отправка с relay при событии `report` | relay + iOS |
| Ответ из уведомления | notification actions → `chat_send` | iOS |
| Быстрые ответы и шаблоны | только iOS (UserDefaults) | iOS |
| Перенос имени, модели, профиля | уже есть в `connect` (`name`, `model`, `profile`, `style`) | — |
